
# 채용공고 분석을 통해 발견한 4가지 인사이트

## 1. 분석 개요

본 문서는 채용공고 기반 직무별 요구 기술 분석 결과에서 확인한 주요 발견을 정리한 것이다.

단순한 기술 등장 빈도를 넘어 직무별 요구 기술의 차이, LLM 관련 기술의 요구 현황, 경력에 따른 요구 기술 수, 직무 간 기술 구성의 유사성을 분석하였다.

분석 결과는 원티드(Wanted) 채용공고 1,273건 중 5개 직무로 재분류된 724건을 기준으로 한다.

---

## 2. 주요 발견

### 발견 1. 데이터 분석가는 Python보다 SQL을 더 자주 요구한다

데이터 분석가 채용공고에서 SQL의 등장률은 **83%**, Python은 **61%**로 나타났다.

SQL의 등장률은 Python보다 약 **23%p** 높았다. 이는 데이터 분석가를 준비할 때 Python뿐 아니라 SQL 역량도 중요하게 고려해야 함을 보여준다.

#### 시사점

데이터 분석가를 목표로 한다면 Python 학습과 함께 SQL을 활용한 데이터 조회, 가공 및 분석 역량을 확보하는 것이 도움이 될 수 있다.

다만 기술의 등장률이 실제 업무 비중이나 요구 숙련도를 의미하는 것은 아니므로, 학습 우선순위를 정하는 참고 지표로 해석해야 한다.

### 발견 2. LLM은 데이터 사이언티스트뿐 아니라 백엔드에서도 요구된다

LLM은 데이터 사이언티스트뿐 아니라 데이터 엔지니어, 백엔드, 프론트엔드 등 다양한 직무의 채용공고에서도 등장하였다.

직무별 LLM 등장률과 공고 수는 다음과 같다.

| 직무 | LLM 등장률 | LLM 등장 공고 수 |
|---|---:|---:|
| 데이터 분석가 | 7% | 5건 |
| 데이터 엔지니어 | 30% | 28건 |
| 데이터 사이언티스트 | 56% | 68건 |
| 백엔드 | 25% | 73건 |
| 프론트엔드 | 19% | 28건 |

#### 분석 결과

- **등장률 기준:** 데이터 사이언티스트가 56%로 가장 높았다.
- **공고 수 기준:** 백엔드가 73건으로 가장 많았다.
- **전체 공고 기준:** 724건 중 202건에서 LLM이 등장하였다.

데이터 사이언티스트는 LLM 등장률이 가장 높아 해당 직무에서 LLM 관련 기술이 상대적으로 자주 요구되는 것으로 나타났다.

반면 백엔드는 LLM 등장률이 25%로 데이터 사이언티스트보다 낮았지만, 전체 공고 수가 많아 LLM이 등장한 공고는 73건으로 가장 많았다.

이는 LLM 관련 기술이 데이터 사이언티스트에만 국한되지 않고, 백엔드 등 다른 개발 직무의 채용공고에서도 요구되고 있음을 보여준다.

#### 시사점

LLM 관련 기술을 학습할 때는 인공지능 모델 개발뿐 아니라 기존 서비스와의 연동 및 활용 관점도 고려할 필요가 있다.

다만 LLM이 채용공고에 등장했다는 사실만으로 해당 직무에서 직접 모델을 개발하거나 운영한다고 단정할 수는 없다.

### 발견 3. 경력이 높아져도 요구 기술 수는 크게 증가하지 않는다

일반적으로 경력이 높아질수록 더 많은 기술을 요구할 것으로 예상할 수 있다.

이를 확인하기 위해 채용공고의 경력 구간별로 공고당 요구 기술 수의 평균과 중앙값을 비교하였다.

| 경력 구간 | 공고 수 | 평균 기술 수 | 중앙값 |
|---|---:|---:|---:|
| 0~1년 | 144건 | 7.0개 | 6개 |
| 2~4년 | 297건 | 7.5개 | 7개 |
| 5년 이상 | 277건 | 7.7개 | 7개 |
| 경력 정보 없음 | 6건 | 7.5개 | 8개 |

#### 분석 결과

- **0~1년:** 평균 7.0개의 기술이 등장하였다.
- **2~4년:** 평균 7.5개의 기술이 등장하였다.
- **5년 이상:** 평균 7.7개의 기술이 등장하였다.

경력이 높아질수록 공고당 평균 요구 기술 수는 소폭 증가하는 경향을 보였다.

그러나 0~1년과 5년 이상 구간의 평균 차이는 **0.7개**에 불과했으며, 2~4년과 5년 이상 구간의 중앙값은 모두 7개로 동일하였다.

따라서 경력이 높아진다고 해서 채용공고에 명시되는 기술의 개수가 크게 증가하는 것은 아니었다.

#### 시사점

경력 수준에 따른 기술 요구의 차이는 단순한 기술 개수보다 요구되는 기술의 종류, 숙련도, 실무 경험 등에서 나타날 가능성이 있다.

다만 본 분석에서는 채용공고에 등장한 기술의 개수만 비교하였으므로, 실제 요구 숙련도나 업무 난이도의 차이까지 확인한 것은 아니다.

### 발견 4. 데이터 엔지니어는 여러 직무와 유사한 기술 구성을 보인다

직무별 요구 기술이 얼마나 유사한지 확인하기 위해 각 직무의 스킬 등장률을 벡터로 표현하고, 코사인 유사도를 계산하였다.

코사인 유사도는 두 벡터의 방향이 얼마나 유사한지 나타내는 지표이다. 이번 분석에서는 값이 1에 가까울수록 두 직무의 기술 등장률 패턴이 유사하다는 의미로 해석하였다.

직무 간 코사인 유사도는 다음과 같다.

| 직무 | 데이터 분석가 | 데이터 엔지니어 | 데이터 사이언티스트 | 백엔드 | 프론트엔드 |
|---|---:|---:|---:|---:|---:|
| 데이터 분석가 | 1.00 | 0.65 | 0.55 | 0.29 | 0.10 |
| 데이터 엔지니어 | 0.65 | 1.00 | 0.65 | 0.64 | 0.20 |
| 데이터 사이언티스트 | 0.55 | 0.65 | 1.00 | 0.54 | 0.25 |
| 백엔드 | 0.29 | 0.64 | 0.54 | 1.00 | 0.60 |
| 프론트엔드 | 0.10 | 0.20 | 0.25 | 0.60 | 1.00 |

#### 분석 결과

- **데이터 엔지니어 - 데이터 분석가:** 유사도 0.65
- **데이터 엔지니어 - 데이터 사이언티스트:** 유사도 0.65
- **데이터 엔지니어 - 백엔드:** 유사도 0.64
- **백엔드 - 프론트엔드:** 유사도 0.60
- **데이터 분석가 - 프론트엔드:** 유사도 0.10

데이터 엔지니어는 데이터 분석가 및 데이터 사이언티스트와 각각 0.65, 백엔드와 0.64의 유사도를 보였다.

이는 데이터 엔지니어가 데이터 관련 직무뿐 아니라 백엔드와도 비교적 유사한 기술 요구 패턴을 가진다는 점을 보여준다.

반면 데이터 분석가와 프론트엔드의 유사도는 0.10으로 낮게 나타나 두 직무의 기술 구성이 뚜렷하게 다름을 확인할 수 있었다.

특히 데이터 엔지니어와 백엔드의 유사도는 0.64로 높았지만, 데이터 분석가 및 데이터 사이언티스트와의 유사도 0.65보다는 소폭 낮았다.

#### 시사점

데이터 엔지니어는 데이터 처리와 분석뿐 아니라 서버 및 인프라 관련 기술도 함께 학습하는 것이 도움이 될 수 있다.

또한 직무 간 기술 요구의 유사성을 활용하면 기존에 학습한 기술을 바탕으로 인접 직무로 역량을 확장하는 방향을 검토할 수 있다.

다만 코사인 유사도는 기술 등장률 패턴의 유사성을 나타내는 지표이며, 실제 업무 내용이나 직무 간 이직 가능성을 직접적으로 의미하지는 않는다.

## 3. 분석의 한계 및 주의사항

본 프로젝트는 채용공고에 등장하는 기술을 정량적으로 분석하여 직무별 요구 기술의 특징을 파악하였다. 그러나 결과를 해석할 때 다음과 같은 한계를 고려해야 한다.

### 3.1 데이터 수집 범위의 한계

- **단일 플랫폼:** 원티드(Wanted)에서 수집한 채용공고만 분석하였으므로 전체 IT 채용시장의 요구 기술을 대표한다고 보기 어렵다.
- **수집 시점:** 특정 시점에 수집한 데이터를 기반으로 하므로 시간에 따른 기술 수요의 변화를 확인하기 어렵다.
- **직무별 표본 차이:** 직무별 분석 공고 수가 서로 달라 등장 공고 수를 직접 비교할 때 주의가 필요하다.

### 3.2 기술 추출 및 직무 분류의 한계

- **스킬 사전 기반 추출:** 표준 기술명 90개와 별칭 210개를 기준으로 기술을 추출하였으므로 사전에 등록되지 않은 기술은 분석에서 누락될 수 있다.
- **텍스트 매칭의 한계:** 기술명이 등장했다는 사실만으로 해당 기술의 필수 여부나 요구 숙련도를 정확하게 판단하기 어렵다.
- **직무 분류의 한계:** 채용공고의 직무명을 기준으로 재분류하였으며, 분석 대상 직무에 해당하지 않거나 분류가 모호한 공고는 제외하였다.

### 3.3 분석 지표 해석의 한계

- **등장률:** 기술이 채용공고에 나타난 비율이며, 실제 업무에서의 사용 빈도나 중요도를 직접적으로 의미하지 않는다.
- **TF-IDF:** 직무별 기술의 상대적인 특징을 보여주는 지표로, 기술의 절대적인 중요도를 나타내지는 않는다.
- **Jaccard 유사도:** 두 기술이 함께 등장하는 비율을 나타내지만, 기술 간 의존관계나 인과관계를 의미하지 않는다.
- **코사인 유사도:** 직무별 기술 요구 패턴의 유사성을 나타내며, 실제 업무 내용이나 직무 간 전환 가능성을 직접적으로 설명하지 않는다.
- **경력별 기술 수:** 공고에 등장한 기술의 개수를 비교한 것으로, 경력에 따른 기술 숙련도나 업무 난이도의 차이를 설명하지는 않는다.

## 4. 최종 정리

이번 분석에서는 채용공고에 명시된 기술을 바탕으로 다음과 같은 네 가지 특징을 확인하였다.

1. **SQL의 중요성:** 데이터 분석가 공고에서는 Python보다 SQL의 등장률이 높았다.
2. **LLM의 다양한 직무 요구:** LLM은 데이터 사이언티스트뿐 아니라 백엔드 등 다양한 직무에서도 요구되었다.
3. **경력별 기술 수의 차이:** 경력이 높아질수록 평균 요구 기술 수는 소폭 증가했지만, 그 차이는 크지 않았다.
4. **직무 간 기술 유사성:** 데이터 엔지니어는 데이터 분석가, 데이터 사이언티스트, 백엔드와 비교적 유사한 기술 요구 패턴을 보였다.

이러한 결과는 직무별 기술 학습 방향을 설정하고, 인접 직무와의 기술적 연관성을 이해하는 데 참고 자료로 활용할 수 있다.

다만 분석 결과는 채용공고에 나타난 기술 요구의 패턴을 설명하는 것이며, 기술 간 인과관계나 실제 채용 성과를 직접적으로 입증하는 것은 아니다.


# 채용공고 기반 직무별 요구 기술 분석 보고서

## 1. 분석 목적

채용공고에 명시된 요구 기술을 분석하여 직무별로 어떤 기술이 중요하게 요구되는지 파악하고자 한다.

단순히 기술의 등장 빈도를 확인하는 데 그치지 않고, 직무별 핵심 기술과 차별화 기술, 함께 요구되는 기술 조합을 분석하여 직무 간 기술 요구의 차이를 확인한다.

이를 통해 취업 준비 과정에서 지원 직무에 적합한 기술을 선정하고, 학습 우선순위를 결정하는 데 활용할 수 있는 객관적인 근거를 마련하는 것이 목적이다.

## 2. 분석 데이터 및 방법

### 2.1 분석 데이터

- **데이터 출처:** 원티드(Wanted) 공개 API
- **수집 공고 수:** 1,273건
- **정제 후 공고 수:** 1,267건 (같은 회사가 같은 제목으로 다시 올린 공고 6건 제거)
- **분석 대상:** 데이터 분석가, 데이터 엔지니어, 데이터 사이언티스트, 백엔드, 프론트엔드
- **최종 분석 공고 수:** 705건
- **분석 제외:** 풀스택 86건, 그 외 직무 476건
- **스킬 사전:** 표준 기술명 90개, 별칭 211개

수집한 채용공고를 제목 기준으로 재분류하고, 분석 대상인 5개 직무에 해당하는 공고를 선별하였다.

| 직무 | 공고 수 |
|---|---:|
| 데이터 분석가 | 71건 |
| 데이터 엔지니어 | 92건 |
| 데이터 사이언티스트 | 155건 |
| 백엔드 | 227건 |
| 프론트엔드 | 160건 |
| **합계** | **705건** |

풀스택 공고는 프론트엔드와 백엔드의 기술이 섞여 어느 한 직무의 결과를 왜곡할 수 있어 별도로 분리하고 분석에서 제외하였다.

이후 채용공고의 텍스트에서 기술명을 추출하고, 공고별 기술 등장 여부를 0과 1로 표현한 스킬 매트릭스를 생성하여 분석에 활용하였다.

분석은 `python run_all.py` 한 번으로 재현할 수 있으며, 각 단계의 실행 결과는 `outputs/logs/`에 저장된다.

### 2.2 분석 방법

**1. 스킬 등장률 분석**

직무별 전체 공고 중 특정 기술이 등장한 공고의 비율을 계산하여 핵심 요구 기술을 파악하였다.

**2. 직무 고유 기술 분석 (TF-IDF, 등장률 차이)**

여러 직무에서 공통으로 요구되는 기술과 특정 직무에서 상대적으로 두드러지는 기술을 구분하기 위해 TF-IDF를 적용하였다. TF-IDF가 직무 5개 단위로 계산되어 등장률 순위를 거의 그대로 따르는 한계가 있어, 해당 직무의 등장률에서 다른 직무 공고의 등장률을 뺀 값(%p)을 함께 계산하였다.

**3. 공동출현 분석**

동일한 채용공고에 함께 등장하는 기술 쌍을 추출하고, 공동출현 횟수와 Jaccard 유사도를 계산하여 기술 간 연관성을 분석하였다.

**4. 추가 인사이트 분석**

LLM의 직무별 등장 현황, 경력 구간별 평균 요구 기술 수, 직무 간 기술 등장률 벡터의 코사인 유사도를 분석하였다.

**5. 통계적 검정**

표본이 작은 직무가 있어 비율에는 Wilson 95% 신뢰구간을 함께 계산하였다. 데이터 분석가의 SQL과 Python 요구는 같은 공고 안에서 짝지어 비교하는 McNemar 정확검정으로, 경력 구간별 요구 기술 수는 Kruskal-Wallis 검정으로 확인하였다.

### 2.3 데이터 검증 및 보정 과정

분석 결과를 만들기 전에 직무 분류와 기술 추출이 제대로 되었는지 표본으로 확인하고, 문제가 발견된 부분은 수정한 뒤 전체 분석을 다시 실행하였다.

#### (1) 중복 공고 정리

공고 ID(`job_id`)는 고유하지만 같은 회사가 같은 제목으로 다시 올린 공고가 6쌍 있었다. 가장 최근 공고만 남기고 제거 내역은 로그로 남겼다. (1,273건 → 1,267건)

#### (2) 직무 분류 검증

직무는 공고 제목의 표현을 규칙으로 분류하였으므로, 분류되지 않고 제외된 공고(other) 중에 분석 대상이 섞여 있는지 확인하였다.

**점검 방법:** other 공고에서 무작위로 50건을 뽑아 제목과 주요 업무를 보고 아래 네 가지로 구분하였다. 기준은 "5개 직무 중 하나의 업무가 주된 포지션인가"이다.

| 구분 | 의미 | 예시 |
|---|---|---|
| 규칙 누락 | 분석 대상이지만 제목 표기가 달라 규칙에 걸리지 않음 | 프론트개발자, Platform Engineer |
| 비대상 | 기획, 영업, PM, IT 운영 등 5개 직무가 아님 | 서비스 기획 담당자, 네트워크 운영 엔지니어 |
| 풀스택 성격 | 프론트엔드와 백엔드를 함께 맡는 포지션 | 프로덕트 엔지니어 |
| 애매 | 직무 범위가 불분명해 판단을 보류 | 스크래핑 엔지니어 |

**1차 점검 결과:** 50건 중 12건(24%, 95% 신뢰구간 14~37%)이 규칙 누락이었다. 누락된 제목은 `프론트개발자`·`프론트 엔지니어`·`Front 개발자`·`프론트엔트`(오타), 영문 `Platform Engineer`·`Infrastructure Engineer`·`DevSecOps`, `AI Research Engineer`·`AI Agent Engineer` 같은 표기였다. 이를 규칙에 추가하였다. 한글로 있는 표기의 영문 변형과 오타만 추가했고, `데이터 아키텍트`·`모바일 엔지니어`처럼 직무 범위가 애매한 표기는 오탐을 막기 위해 추가하지 않았다.

**재점검 결과:** 규칙을 고친 뒤 other를 새로 무작위 50건 뽑아 같은 기준으로 구분하자 규칙으로 잡을 수 있는 누락은 3건(6%)으로 줄었다. 이 중 1건(`AI Agent 개발자`)은 같은 계열이라 규칙을 추가하였다. 남은 제외 공고는 대부분 기획, 영업, PM 등 분석 대상이 아닌 직무였다.

**풀스택 분리:** 수집 카테고리가 프론트엔드인 공고 중 일부가 백엔드로 분류되고 있었는데, 확인해 보니 풀스택 공고였다. `풀스택` 표기가 있는 공고 86건을 별도 라벨로 분리하자, 프론트엔드 카테고리에서 백엔드로 분류된 공고가 94건에서 29건으로 줄었다.

**규칙 추가 효과:** 규칙 추가 전후를 전체 공고로 비교하여, 의도한 공고만 이동하고 이미 분류된 공고는 바뀌지 않는 것을 확인하였다.

#### (3) 기술 추출 검증

기술은 스킬 사전의 별칭을 텍스트에서 찾는 방식으로 추출하므로, 별칭이 다른 단어 안의 글자까지 잡는지 표본으로 확인하였다.

**점검 방법:** 분석 대상 705건에서 등장 공고가 많은 상위 20개 기술마다 무작위 10문장, 일반 영어 단어와 겹칠 수 있는 15개 기술(Excel, Slack, Spark, Spring, Oracle, Swift, Go, R 등)마다 최대 8문장을 뽑아 약 300문장을 직접 확인하였다. 기술을 잘못 잡은 사례는 발견되지 않았다. 다만 `GitHub, 기술 블로그, 오픈소스 활동 경험`(포트폴리오 링크), `엑셀 내보내기 기능 구현`, `Slack 미들웨어 구현`처럼 기술이 언급은 되었지만 숙련 요구로 보기 어려운 문맥이 3건 있었다. 이는 사전 기반 추출 방식의 한계이다.

**수정 과정에서 발견한 문제:** 분석 결과를 검토하는 과정에서 아래 문제를 발견하여 수정하였다.

| 문제 | 원인 | 수정 |
|---|---|---|
| 데이터 분석가 공고의 11%가 Vue.js를 요구하는 것으로 집계됨 | Vue.js 별칭 `뷰`가 `리뷰`, `웹뷰`, `인터뷰` 같은 단어 안의 글자까지 매칭 | 별칭 삭제, 한글로 시작하는 별칭은 앞에 한글이 붙은 경우 매칭하지 않도록 경계 조건 추가 |
| ETL이 한 건도 집계되지 않음 | `\b`로 시작하는 정규식 별칭이 대소문자를 구분해 대문자 `ETL`을 놓침 | 일반 별칭으로 변경 (`etl`, `elt`, `k8s`, `cicd`, `git`) |

### 3.2 직무를 구별하는 기술 - TF-IDF와 등장률 차이

단순 등장률만으로는 특정 기술이 해당 직무를 얼마나 특징적으로 나타내는지 판단하기 어렵다.

예를 들어 Python은 여러 직무에서 공통으로 요구되기 때문에 등장률이 높더라도 특정 직무만의 차별화 기술이라고 보기 어렵다.

이를 보완하기 위해 TF-IDF를 적용하여 직무별 기술의 상대적인 중요도를 분석하고, 한계를 확인한 뒤 등장률의 차이를 직접 계산하는 방법을 추가하였다.

#### 분석 방법

- **TF(Term Frequency):** 해당 직무의 채용공고에서 특정 기술이 등장한 비율
- **DF(Document Frequency):** 특정 기술의 등장률이 5% 이상인 직무의 수
- **IDF(Inverse Document Frequency):** 여러 직무에 공통으로 등장하는 기술의 가중치를 낮추는 값
- **TF-IDF:** TF와 IDF를 곱하여 특정 직무에서 상대적으로 두드러지는 기술을 파악하는 지표
- **등장률 차이(%p):** 해당 직무의 등장률에서 해당 직무가 아닌 모든 공고의 등장률을 뺀 값

이번 분석에서는 개별 채용공고가 아닌 직무를 TF-IDF의 비교 단위로 사용하였다.

#### TF-IDF 결과와 한계

직무별 TF-IDF 값이 높은 상위 3개 기술은 다음과 같다.

| 직무 | 1위 | 2위 | 3위 |
|---|---|---|---|
| 데이터 분석가 | SQL (0.982) | Tableau (0.887) | Python (0.716) |
| 데이터 엔지니어 | Python (0.822) | Kafka (0.755) | SQL (0.745) |
| 데이터 사이언티스트 | Python (0.854) | PyTorch (0.691) | Deep Learning (0.636) |
| 백엔드 | Kubernetes (0.719) | AWS (0.612) | CI/CD (0.609) |
| 프론트엔드 | React (1.598) | TypeScript (1.160) | Next.js (0.921) |

![직무별 특징 기술 TF-IDF 히트맵](../outputs/figures/pc_a3_tfidf_heatmap.png)

TF-IDF 값은 등장률 자체가 아닌 가중치가 적용된 지표이므로, 값이 1을 초과할 수 있다.

다만 문서의 단위가 공고가 아니라 직무 5개이므로 IDF가 가질 수 있는 값이 5가지뿐이다. 그래서 결과가 등장률 순위를 거의 그대로 따라가고, 데이터 엔지니어의 1위가 모든 데이터 직무에서 흔한 Python으로 나오는 등 직무를 구별하는 기술이라는 의미가 약해진다.

#### 등장률 차이(%p) 결과

이를 보완하기 위해 해당 직무의 등장률에서 다른 직무 공고 전체의 등장률을 뺀 값을 계산하였다. 상위 3개 기술은 다음과 같다.

| 직무 | 1위 | 2위 | 3위 |
|---|---|---|---|
| 데이터 분석가 | SQL (+66%p) | Tableau (+41%p) | A/B Test (+33%p) |
| 데이터 엔지니어 | Airflow (+47%p) | SQL (+45%p) | Spark (+44%p) |
| 데이터 사이언티스트 | LLM (+35%p) | Python (+33%p) | PyTorch (+31%p) |
| 백엔드 | Kubernetes (+46%p) | CI/CD (+34%p) | AWS (+33%p) |
| 프론트엔드 | React (+88%p) | TypeScript (+74%p) | Next.js (+51%p) |

![직무별 고유 기술 등장률 차이 히트맵](../outputs/figures/pc_a3_gap_heatmap.png)

히트맵은 상위 기술의 등장률 차이를 직무별로 비교한 결과이다. 빨간색은 해당 직무에서 다른 직무보다 더 많이 요구되는 기술을, 파란색은 덜 요구되는 기술을 의미한다.

- **데이터 분석가:** SQL과 Tableau, A/B Test가 두드러졌다. Tableau는 데이터 분석가에서 42%, 다른 직무에서는 1%만 등장하였다.

- **데이터 엔지니어:** Airflow(+47%p), Spark(+44%p), ETL(+39%p), Kafka(+36%p), dbt(+28%p) 등 데이터 파이프라인 기술이 상위에 나타났다. TF-IDF에서 1위였던 Python은 +27%p로 7위였다.

- **데이터 사이언티스트:** LLM과 PyTorch, Machine Learning, Deep Learning이 상위에 나타났다. Python도 +33%p로 높은데, 프론트엔드(4%)와 백엔드(44%) 공고에서는 데이터 사이언티스트(72%)보다 Python이 덜 요구되기 때문이다.

- **백엔드:** Kubernetes, CI/CD, AWS, Terraform 등 인프라 및 배포 관련 기술이 상위에 나타났다.

- **프론트엔드:** React, TypeScript, Next.js, JavaScript, CSS 등 웹 프론트엔드 개발 기술이 상위에 나타났다.

#### 시사점

직무별 기술 학습 전략을 수립할 때는 등장률이 높은 핵심 기술과 다른 직무와의 등장률 차이가 큰 차별화 기술을 함께 고려할 필요가 있다. 예를 들어 데이터 엔지니어는 Python과 SQL이 기본이라면, 직무를 구별하는 기술은 Airflow, Spark, ETL, Kafka이다.

### 3.3 함께 요구되는 기술 - 공동출현 분석

채용공고에서 개별 기술의 등장 빈도뿐 아니라, 동일한 공고에 함께 등장하는 기술 조합을 파악하기 위해 공동출현 분석을 수행하였다.

단순 공동출현 횟수는 등장 빈도가 높은 기술에 유리하므로, 이를 보완하기 위해 Jaccard 유사도를 함께 계산하였다.

#### 분석 방법

- **공동출현 횟수:** 두 기술이 동일한 채용공고에 함께 등장한 횟수
- **Jaccard 유사도:** 두 기술 중 하나라도 등장한 공고 대비 두 기술이 함께 등장한 공고의 비율
- **분석 대상:** 전체 분석 공고에서 20건 이상 등장한 기술

Jaccard 유사도는 0에서 1 사이의 값을 가지며, 값이 높을수록 두 기술이 같은 공고에 함께 등장하는 비율이 높다는 의미이다.

#### 분석 결과

공동출현 횟수가 높은 기술 조합은 다음과 같다.

| 기술 조합 | 공동출현 횟수 | Jaccard 유사도 |
|---|---:|---:|
| TypeScript + React | 154건 | 0.733 |
| Python + AWS | 144건 | 0.316 |
| AWS + CI/CD | 131건 | 0.383 |
| AWS + Kubernetes | 131건 | 0.373 |
| Python + SQL | 126건 | 0.341 |

#### 기술 공동출현 네트워크

![기술 공동출현 네트워크](../outputs/figures/pc_a4_network.png)

네트워크 그래프는 Jaccard 유사도가 0.2 이상인 기술 조합을 시각화한 결과이다. 노드는 개별 기술을, 연결선은 기술 간 공동출현 관계를 나타낸다.

TypeScript와 React는 공동출현 횟수와 Jaccard 유사도가 모두 높아 밀접하게 함께 요구되는 기술 조합으로 나타났다.

반면 Python과 AWS는 공동출현 횟수가 많지만 Jaccard 유사도는 상대적으로 낮았다. 이는 두 기술이 각각 다양한 공고에서 폭넓게 등장하기 때문일 수 있다.

또한 Android와 iOS는 공동출현 횟수가 25건이지만 Jaccard 유사도가 0.926으로 가장 높게 나타났다. 이는 기술 조합의 밀접성을 판단할 때 단순 등장 횟수뿐 아니라 Jaccard 유사도를 함께 고려해야 함을 보여준다. HTML + CSS(0.571), Jira + Slack(0.547), React + Next.js(0.526)도 함께 쓰이는 비율이 높은 조합이었다.

다만 공동출현 횟수가 적은 기술 조합은 상대적으로 적은 표본에 영향을 받을 수 있으므로, 유사도와 등장 횟수를 함께 해석해야 한다.

기술 사전을 보정하기 전에는 `Spring + Spring Boot`, `GitHub Actions + Git`, `React + Vue.js`가 상위 조합에 나타났다. 앞의 두 조합은 한 기술의 이름 안에 다른 기술의 이름이 들어 있어서, 마지막 조합은 Vue.js 별칭 오탐 때문에 생긴 결과였고 보정 후에는 상위 조합에서 사라졌다.

#### 시사점

채용공고에서는 기술이 개별적으로 요구되기보다 특정 기술 조합으로 등장하는 경우가 있다.

따라서 취업 준비 과정에서 기술을 하나씩 독립적으로 학습하는 것뿐 아니라, 지원 직무에서 함께 요구되는 기술을 묶어 학습하는 전략도 고려할 수 있다.

### 3.4 LLM 요구 현황 분석

최근 AI 관련 기술 중 하나인 LLM이 분석 대상 직무에서 얼마나 요구되는지 확인하였다.

#### 분석 결과

전체 분석 공고 705건 중 LLM이 등장한 공고는 196건(27.8%)이었다.

| 직무 | 분석 공고 수 | LLM 등장률 (95% 신뢰구간) | LLM 등장 공고 수 |
|---|---:|---:|---:|
| 데이터 분석가 | 71건 | 7% (3~15%) | 5건 |
| 데이터 엔지니어 | 92건 | 30% (22~40%) | 28건 |
| 데이터 사이언티스트 | 155건 | 55% (47~62%) | 85건 |
| 백엔드 | 227건 | 22% (17~28%) | 50건 |
| 프론트엔드 | 160건 | 18% (12~24%) | 28건 |
| **합계** | **705건** | **28%** | **196건** |

데이터 사이언티스트는 LLM 등장률과 등장 공고 수가 모두 가장 높았다.

그러나 LLM이 등장한 196건 중 111건(57%)은 데이터 사이언티스트가 아닌 직무의 공고였다. 데이터 엔지니어는 30%, 백엔드는 22%, 프론트엔드는 18%에서 LLM이 등장하였다.

이는 LLM 관련 기술이 데이터 사이언티스트뿐 아니라 데이터 엔지니어, 백엔드, 프론트엔드 등 다른 직무의 채용공고에서도 요구되고 있음을 보여준다.

다만 데이터 사이언티스트 직무 분류 규칙에는 제목에 `LLM`이 들어간 공고가 포함되어 있다. 데이터 사이언티스트의 LLM 공고 85건 중 16건은 제목에 LLM이 있어 분류 단계에서 이미 LLM이 반영된 공고이므로, 데이터 사이언티스트의 LLM 등장률은 다소 높게 나왔을 수 있다.

#### 시사점

LLM 관련 역량을 준비할 때는 AI 모델 자체에 대한 이해뿐 아니라, 지원 직무에서 LLM을 어떤 방식으로 활용하는지 확인할 필요가 있다.

### 3.5 경력별 요구 기술 수 분석

경력 수준에 따라 채용공고에서 요구하는 기술의 개수가 달라지는지 분석하였다.

#### 분석 결과

| 경력 구간 | 공고 수 | 평균 요구 기술 수 | 중앙값 | 표준편차 |
|---|---:|---:|---:|---:|
| 0~1년 | 131건 | 6.4개 | 6개 | 4.6개 |
| 2~4년 | 294건 | 7.1개 | 6개 | 4.0개 |
| 5년 이상 | 273건 | 7.2개 | 7개 | 4.1개 |
| 경력 미상 | 7건 | 6.9개 | 6개 | 5.0개 |

경력 수준이 높아질수록 평균 요구 기술 수는 소폭 높아지는 경향이 있었다.

그러나 0~1년과 5년 이상 구간의 평균 차이는 약 0.8개로 구간별 표준편차(4.0~4.6개)보다 훨씬 작았다. 경력 미상을 제외한 세 구간을 Kruskal-Wallis 검정으로 비교한 결과 H = 5.79, p = 0.055로 5% 유의수준에서 통계적으로 유의하지 않았으나 경계에 가까운 값이었다. 경력 수준에 따라 요구 기술 수가 크게 달라지는 패턴은 확인되지 않았다.

다만 요구 기술의 개수만으로 실제 기술 숙련도나 업무 난이도를 판단할 수는 없다.

#### 시사점

경력에 따른 채용 요구를 이해할 때는 단순히 기술의 개수뿐 아니라, 기술별 요구 숙련도와 실제 담당 업무를 함께 살펴볼 필요가 있다.

### 3.6 직무 간 기술 요구 패턴 유사도 분석

서로 다른 직무에서 요구하는 기술 구성이 얼마나 유사한지 확인하기 위해 직무별 기술 등장률 벡터의 코사인 유사도를 계산하였다.

#### 분석 방법

각 직무에서 기술별 등장률을 벡터로 구성한 뒤, 두 직무 벡터 사이의 코사인 유사도를 계산하였다.

코사인 유사도는 두 벡터의 방향이 얼마나 유사한지를 나타내며, 이번 분석에서는 값이 1에 가까울수록 두 직무의 기술 요구 패턴이 유사하다고 해석하였다.

#### 직무 간 코사인 유사도 히트맵

![직무 간 코사인 유사도](../outputs/figures/pc_a5_role_similarity.png)

#### 분석 결과

데이터 엔지니어는 다음 직무와 비교적 높은 유사도를 보였다.

- 백엔드: 0.67
- 데이터 분석가: 0.64
- 데이터 사이언티스트: 0.64

또한 백엔드와 데이터 사이언티스트의 유사도는 0.57, 백엔드와 프론트엔드의 유사도는 0.42로 나타났다.

반면 데이터 분석가와 프론트엔드의 유사도는 0.08로 상대적으로 낮았다.

이는 데이터 엔지니어가 데이터 분석, 데이터 사이언스 및 백엔드와 일부 기술 요구 패턴을 공유하며, 특히 백엔드와 가장 유사한 반면, 데이터 분석가와 프론트엔드는 기술 구성이 상대적으로 다르다는 점을 보여준다.

#### 시사점

직무 간 기술 요구 패턴의 유사도를 확인하면 인접 직무로의 역량 확장 가능성을 탐색하거나, 여러 직무에서 공통으로 요구되는 기술을 파악하는 데 참고할 수 있다.

다만 코사인 유사도가 높다고 해서 실제 업무 내용이나 직무 전환 난이도까지 동일하다는 의미는 아니다.

## 4. 종합 결론

본 프로젝트에서는 원티드 채용공고 1,273건을 수집하고, 중복을 정리한 1,267건 중 5개 직무로 분류된 705건을 대상으로 요구 기술을 분석하였다.

스킬 등장률 분석을 통해 직무별 주요 요구 기술의 차이를 확인하였으며, TF-IDF와 등장률 차이 분석을 통해 특정 직무에서 상대적으로 두드러지는 기술을 파악하였다.

또한 공동출현 분석과 Jaccard 유사도를 활용하여 함께 요구되는 기술 조합을 확인하고, LLM 요구 현황, 경력별 기술 수, 직무 간 코사인 유사도를 추가로 분석하였다.

### 주요 결론

1. **직무별 기술 요구의 차이:** 동일한 IT 분야에서도 직무에 따라 핵심적으로 요구되는 기술이 다르게 나타났다.

2. **기술의 등장률과 차별성:** 자주 등장하는 기술이 반드시 특정 직무만의 특징적인 기술을 의미하지는 않는다. 데이터 엔지니어에서는 Python이 가장 많이 등장하지만 직무를 구별하는 기술은 Airflow, Spark, ETL, Kafka였으므로, 등장률과 다른 직무와의 등장률 차이를 함께 고려할 필요가 있다.

3. **기술 조합의 중요성:** 채용공고에서 여러 기술이 함께 요구되는 패턴을 확인하였으며, 기술 스택 단위의 학습 전략이 유용할 수 있음을 확인하였다.

4. **LLM 요구의 확장:** LLM이 등장한 공고의 57%는 데이터 사이언티스트가 아닌 직무의 공고였다. 데이터 엔지니어(30%), 백엔드(22%), 프론트엔드(18%) 공고에서도 LLM이 요구되었다.

5. **경력별 기술 수의 차이:** 경력 구간별 평균 요구 기술 수는 6.4개에서 7.2개로 소폭 높아졌지만 통계적으로 유의하지 않았고(p = 0.055), 기술의 개수만으로 요구 역량의 수준을 판단하기는 어려웠다.

6. **직무 간 기술 요구의 유사성:** 데이터 엔지니어는 백엔드(0.67), 데이터 분석가(0.64), 데이터 사이언티스트(0.64)와 비교적 유사한 기술 요구 패턴을 보였으며 특히 백엔드와 가장 유사하였다.

이러한 분석 결과는 취업 준비자가 지원 직무에 필요한 기술을 파악하고 학습 우선순위를 설정하는 데 참고 자료로 활용할 수 있다.

### 분석의 한계

본 분석은 원티드라는 단일 플랫폼에서 수집한 채용공고를 기반으로 하므로 전체 채용시장의 요구 기술을 대표한다고 보기는 어렵다.

또한 스킬 사전에 등록된 기술의 텍스트 등장 여부를 분석하였으므로, 사전에 포함되지 않은 기술이나 문맥에 따른 의미 차이를 완전히 반영하기 어렵다. 표본 점검에서도 기술이 언급은 되었지만 숙련 요구로 보기 어려운 문맥이 일부 확인되었다.

직무는 공고 제목의 표현으로 분류하였다. 제외된 공고(other)를 표본으로 점검했을 때 규칙으로 잡을 수 있는 누락은 약 6%였지만, `음성인식 엔지니어`처럼 제목에 직무 키워드가 없는 경우는 규칙으로 구분하기 어려워 일부 누락이 남아 있을 수 있다. 점검 기준은 한 사람이 판단한 것이어서 판정자 간 일치도는 확인하지 못했다. 풀스택 공고는 분석에서 제외하였으므로 풀스택 직무의 기술 요구는 이 분석에 포함되지 않는다.

직무별 분석 공고 수는 71~227건으로 차이가 있고 데이터 분석가는 71건에 불과하다. 이 때문에 비율에는 신뢰구간을 함께 제시하였다. 또한 여러 지표에 대해 검정을 수행하였으나 다중 비교 보정은 하지 않았으므로, p값은 참고용으로 해석해야 한다.

따라서 본 분석 결과는 채용공고에 나타난 기술 요구의 패턴을 보여주는 참고 자료이며, 기술의 실제 숙련도나 채용 성공에 미치는 인과적 영향을 직접적으로 설명하지는 않는다.
